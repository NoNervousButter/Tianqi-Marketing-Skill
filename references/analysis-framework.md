# 案例分析框架

## 案例概览
一段话交代品牌、活动节点、主题、主推商品与优惠。表格按实际可得信息记录：品牌、活动名称、活动时间及其时区、EDM发送时间、核心商品、活动规则、触达渠道。区分活动和互动挑战各自时间，未知注明未确认。

## 独立站活动页拆解
按实际页面顺序逐模块分析，如入口和Hero、活动机制、商品和选型、套装、配件、互动、FAQ、购物车与页尾。每个模块说明：可见内容和交互 → 在用户路径中的作用 → 具体不足、疑问或机会。不要固定要求页面包含所有模块。关注优惠门槛及适用范围、CTA、选品路径、信任和客单价；不把设计意图写成已验证的效果。末尾用简短段落总结活动路径和可借鉴处。

## EDM邮件拆解
开头说明发送时间、活动阶段、本封任务；列Subject和Preheader并分析打开理由、利益及分工。按邮件实际顺序拆解导航、Hero、正文、活动玩法、商品、CTA、服务权益和Footer；将视觉、文案、交互、作用及具体不足联系起来。分析邮件与落地页的衔接；多封时可比较节奏、诉求和素材复用，但不能以不完整归档断言全量发送频率。日期和预览文案有来源差异时保留差异。

结尾写“可关注内容”，最多3条，优先挑低成本、可复刻、适合自身品牌学习的优点，每条给出具体应用方式，并在相关时指出Omnisend待核对项。原邮件事实和建议改进明确区分；没有实际检查Omnisend时不要称已核对。用户另有数量或范围要求时遵从用户。

## 写作
中文业务分析语言，连贯、具体、克制。先描述可观察内容，再解释其作用，再指出不足或验证边界。用截图和链接支撑事实；未经数据支持，用“有助于”“可能”而非断言效果。不重复堆砌通用营销术语，不从单次截图推断中奖概率、转化或用户分层。
